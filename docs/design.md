# Slint Omarchy implementation

This project uses the 48 previews in `../gpui-omarchy/examples/gallery/app.rs` as its functional checklist. The purpose is to compare Slint's development experience and runtime behavior against the GPUI implementation, while keeping Omarchy's flat geometry, restrained colors, and keyboard-oriented controls.

The app is a single gallery window. `ui/omarchy.slint` is the public component entry point; it re-exports the theme and controls from focused Slint modules for actions, forms, inputs, navigation, content, collections, data views, overlays, feedback, layout, and the title bar. `ui/gallery.slint` imports those components and owns preview composition and state; `ui/gallery_examples.slint` contains example-specific forms and sample split panes. See [UI architecture](architecture.md) for the public interface and layout rules. `examples/reuse.rs` checks that another window can import and bind the public controls. Rust owns system theme loading and any data or interactions that need host APIs. Each preview should be interactive enough to exercise the component, not merely a static drawing. The benchmark views should use large data sets and report measurements separately from design comparisons.

Current implementation: the gallery provides a preview for 46 of the 48 reference entries, including theme-aware scrolling, a 1,000-row virtual list, text editing, selection, a table, calendar, date picker, color editing, a tree, resizable panes, and custom vertical and horizontal scrollbars. Dock and OTP input are deferred because their current implementations are incomplete. System theme mode follows changes every two seconds. Some previews still cover fewer states or interactions than the GPUI originals; an implemented entry means that its preview exists, not that it has complete feature parity. The next work is to deepen those previews and keyboard and focus behavior, then measure startup and scrolling performance under the same conditions. A first idle memory comparison is recorded in `docs/performance.md`.
